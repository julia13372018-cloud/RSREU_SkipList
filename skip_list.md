# Алгоритм Skip List (список с пропусками)

## Определение

Skip List — вероятностная структура данных, представляющая собой иерархию отсортированных связных списков. Базовый уровень содержит все элементы в порядке возрастания ключей. Каждый вышележащий уровень является подмножеством нижележащего и служит «экспресс-линией» для ускорения поиска.

## Структура

Каждый узел хранит:
- ключ (значение элемента)
- массив указателей `forward[]`, где `forward[i]` указывает на следующий узел на уровне `i`

Длина массива `forward[]` определяется случайным образом при создании узла и называется уровнем узла. Уровень 0 — базовый, присутствует у всех узлов.

Дополнительно используется фиктивный узел `header`, из которого начинается обход на всех уровнях.

## Вероятностная генерация уровней

При вставке нового узла его уровень определяется итеративным процессом:
1. Начальный уровень `lvl = 0`
2. С вероятностью `p` (обычно 0.5) уровень увеличивается на 1
3. Процесс повторяется до достижения максимального уровня `max_level` или до неудачного «подбрасывания»

Математическое ожидание уровня узла: `1/(1-p)`. При `p = 0.5` средний уровень ≈ 2. Это обеспечивает пирамидальную структуру: на уровне 0 — все N элементов, на уровне 1 — примерно N/2, на уровне 2 — N/4, и так далее.

## Операция поиска

Алгоритм поиска ключа `key`:

1. Установить текущий узел `current = header`
2. Для каждого уровня `i` от текущего максимального до 0:
   - Пока `current.forward[i]` существует и его ключ меньше `key`:
     - Перейти: `current = current.forward[i]`
3. Перейти на базовый уровень: `current = current.forward[0]`
4. Если `current` не равен `null` и `current.key == key` — элемент найден

Поиск начинается с верхнего уровня, где элементы расположены редко, и быстро приближается к искомому ключу. Затем спускается на уровень ниже для уточнения позиции. Процесс повторяется до базового уровня.

Пример: при поиске ключа 25 в списке `[3, 7, 12, 19, 25, 30]` алгоритм может сделать переходы: `header → 19` (уровень 3), затем `19 → 25` (уровень 0). Всего 2 перехода вместо 5 в обычном связном списке.

## Операция вставки

Алгоритм вставки ключа `key`:

1. Создать массив `update[]` размером `max_level + 1`
2. Установить `current = header`
3. Для каждого уровня `i` от текущего максимального до 0:
   - Пока `current.forward[i]` существует и его ключ меньше `key`:
     - Перейти: `current = current.forward[i]`
   - Сохранить: `update[i] = current` (предшественник на уровне `i`)
4. Перейти на базовый уровень: `current = current.forward[0]`
5. Если `current` равен `null` или `current.key != key` (ключ отсутствует):
   - Сгенерировать случайный уровень `rlevel` для нового узла
   - Если `rlevel > current_level` (текущий максимальный уровень списка):
     - Для уровней от `current_level + 1` до `rlevel`: `update[i] = header`
     - Обновить: `current_level = rlevel`
   - Создать новый узел `new_node` с уровнем `rlevel`
   - Для каждого уровня `i` от 0 до `rlevel`:
     - `new_node.forward[i] = update[i].forward[i]`
     - `update[i].forward[i] = new_node`

Массив `update[]` хранит предшественников нового узла на каждом уровне. Это позволяет вставить узел за один проход без повторного поиска.

## Операция удаления

Алгоритм удаления ключа `key`:

1. Создать массив `update[]` размером `max_level + 1`
2. Установить `current = header`
3. Для каждого уровня `i` от текущего максимального до 0:
   - Пока `current.forward[i]` существует и его ключ меньше `key`:
     - Перейти: `current = current.forward[i]`
   - Сохранить: `update[i] = current`
4. Перейти на базовый уровень: `current = current.forward[0]`
5. Если `current` не равен `null` и `current.key == key`:
   - Для каждого уровня `i` от 0 до `current_level`:
     - Если `update[i].forward[i] != current`: прервать цикл (узла нет на этом и более высоких уровнях)
     - `update[i].forward[i] = current.forward[i]` (удалить узел из уровня `i`)
   - Освободить память, занятую `current`
   - Пока `current_level > 0` и `header.forward[current_level] == null`:
     - Уменьшить: `current_level = current_level - 1`

Удаление использует тот же механизм поиска предшественников, что и вставка. После удаления узла из всех уровней, на которых он присутствовал, проверяется, не опустели ли верхние уровни, и при необходимости уменьшается `current_level`.

## Асимптотическая сложность

- **Поиск:** O(log N) в среднем
- **Вставка:** O(log N) в среднем
- **Удаление:** O(log N) в среднем
- **Память:** O(N) в среднем

Логарифмическая сложность достигается за счёт вероятностной структуры: на каждом уровне количество элементов уменьшается в `1/p` раз. При `p = 0.5` высота списка в среднем равна `log₂(N)`, и на каждом уровне делается не более одного перехода.

Строгое математическое доказательство оценки O(log N) основано на анализе обратного пути поиска (от целевого элемента к header) и показывает, что ожидаемое количество переходов не превышает `log_{1/p}(N)`.

## Практические особенности

1. **Дубликаты.** Базовая реализация игнорирует дубликаты. Для поддержки дубликатов узел может хранить счётчик или список значений.

2. **Расход памяти.** Каждый узел хранит массив указателей длиной `level + 1`. Средний расход памяти на узел: `sizeof(key) + sizeof(pointer) * (1/(1-p) + 1)`. При `p = 0.5` это примерно `sizeof(key) + 3 * sizeof(pointer)`.

3. **Конкурентность.** Skip List легче адаптировать для многопоточной среды, чем сбалансированные деревья. Изменение указателей в связном списке атомарно, что позволяет реализовать lock-free или fine-grained locking версии с минимальными блокировками.

4. **Кэширование.** Из-за нерегулярной структуры указателей Skip List хуже использует кэш процессора по сравнению с массивами или сбалансированными деревьями, хранящими узлы в компактной памяти.

## Применение

Skip List используется в:
- Redis (Sorted Sets) — для хранения отсортированных множеств в памяти
- LevelDB, RocksDB, Cassandra — для memtable (in-memory буфера записи)
- Java (`ConcurrentSkipListMap`, `ConcurrentSkipListSet`) — для конкурентных отсортированных коллекций
- Apache Lucene — для хранения термов в инвертированном индексе

Выбор Skip List в этих системах обусловлен балансом между простотой реализации, приемлемой производительностью и возможностью эффективной многопоточной обработки.
